camus-cli

camus-cli is the command-line SQL shell for CamusDB. Use it to try a query, test a transaction, or read a query plan from a terminal. It can also execute .sql files in CI and take backups. The prompt has syntax coloring and completion, and scripts can read JSON or YAML output.

For a browser workspace, see Web Console. To connect from an application, use a driver, such as the .NET driver or the Python driver.

Quick start​

Install the .NET tool:

dotnet tool install --global CamusDB.SqlSh

Connect to a local server:

camus-cli              # no current database
camus-cli northwind    # current database "northwind"

The shell tries gRPC on http://localhost:5096. If that fails, it tries REST on http://localhost:5095. The banner shows the endpoint and the transport. If you don't give a database name, select one with use:

CREATE DATABASE IF NOT EXISTS test;
USE test;

To update the tool, run dotnet tool update --global CamusDB.SqlSh.

Connect with a connection string​

camus-cli -c "Endpoint=https://db.example.com:5095;Database=northwind"
camus-cli -c "Endpoint=http://node1:5096,http://node2:5096;Protocol=grpc"
  • Endpoint is required. It can be a comma-separated list of nodes.
  • Without Protocol, the shell tries gRPC, then REST, on the same endpoint. Protocol=grpc or Protocol=rest uses one transport only.
  • -c takes the connection string keys of the .NET driver.
  • The shell connects at startup. An endpoint that can't be reached returns an error at once.

Server-level statements, such as CREATE DATABASE and SHOW DATABASES, don't need a current database. Statements on tables need one.

Interactive shell​

The prompt is camus>. A statement that continues on more lines shows ->. The shell handles the following commands. It sends all other text to the server as SQL.

\dt, \dv, \dm, \ds, \di [pattern]List tables, views, materialized views, sequences, or indexes.

\lList databases.

A / prefix works the same as \ for \d, \df, \l, \plan, and \export.

Edit and run statements​

Enter sends the statement. It starts a new line in the following cases:

  • The statement has an open quote or parenthesis.
  • The statement has an open $$ body.
  • The line ends with a comma.

A pasted Enter adds a line, and it doesn't send the statement.

The editor colors the SQL syntax. The inline functions of the current database are colored as functions.

select * from us<Tab>
with t as (select 1) select * from <Tab>
show ranges from index users@<Tab>

Switch databases​

use northwind;
use `order details`;

use reconnects with the new database, which must exist. Quote a name that is a keyword or has spaces, with backticks or double quotes. use also works in scripts. This means that a script can change databases.

Transactions​

begin;
update accounts set balance = balance - 100 where id = 1;
update accounts set balance = balance + 100 where id = 2;
commit;
  • Only one transaction can be open at a time.
  • exit and use return an error while a transaction is open. Run commit or rollback before them.
  • If a statement in the transaction fails, the transaction ends. This also applies to a failed commit or rollback.

start transaction is the same as begin. See Transactions.

History​

The shell saves the last 2,000 statements at exit and on Ctrl+C.

PlatformPath
Any, when XDG_STATE_HOME is set$XDG_STATE_HOME/camusdb/history.json
Linux and macOS~/.config/camusdb/history.json
Windows%LOCALAPPDATA%\camusdb\history.json

Only your user can read the file. A statement with a password, such as CREATE USER … IDENTIFIED BY or ALTER USER, isn't saved to disk. Up recalls it until the session ends. --no-history turns history off.

Inline functions and triggers​

Type inline C# functions and triggers as ordinary SQL. The shell reads the dollar-quoted body as raw text:

CREATE FUNCTION slugify(s STRING) RETURNS STRING LANGUAGE csharp AS $$
    return s.Trim().ToLowerInvariant().Replace(' ', '-');
$$;

CREATE TRIGGER slug ON posts BEFORE INSERT, UPDATE LANGUAGE csharp AS $$
    if (NEW!.title is { } title)
        NEW.slug = slugify(title);
$$;
  • The body can contain semicolons, quotes, and comments.
  • Enter in an open body adds a line. The statement is sent after the closing $$ and ;.
  • A body that contains $$ uses a tagged quote, such as $fn$ … $fn$.

\df lists the inline functions of the current database. \df+ adds the generation, the compile state on this node, and the CREATE FUNCTION statement. \d <table> lists the table's triggers.

When a body doesn't compile (CADB0838), or uses a type or member that isn't allowed (CADB0839), the shell marks the position with a caret:

CamusException (CADB0838): Function 'broken' does not compile: (2,12): CS0103: The name 'z' does
not exist in the current context

      return z.Trim();
             ^ CS0103: The name 'z' does not exist in the current context

Output​

+----+------+
| id | name |
+----+------+
| 1  | Ada  |
+----+------+
1 rows in set (00:00:00.0123456)

Query OK, 1 rows affected (00:00:00.0123456)
  • Queries print a table. DDL prints Query OK, and writes print the affected row count.
  • A write with RETURNING prints the returned rows, and then Query OK.
  • A statement after a WITH clause decides the output. WITH … SELECT prints rows, and WITH … UPDATE … RETURNING prints the returned rows.
  • Values print in a form that you can type back into SQL. For example, BYTES prints as an x'…' literal, and NUMERIC prints all its digits.

An error shows its error code and message. When the message gives a position, the shell prints the line with a ^ under the column. Some errors add a hint. For example, CADB0560 and CADB0561 show the SET CLUSTER SETTING statement that raises the limit.

Vertical output​

End a statement with \G in place of ; to print one column per line. This helps with wide rows and long JSON values.

camus> select * from users\G
*************************** 1. row ***************************
  id: 1
name: Ada
1 rows in set (00:00:00.0123456)

\plan table prints the raw plan rows, and \plan flow returns to the diagram. \G, --format json|yaml, and --tui always print the raw rows. See EXPLAIN.

Export a result set​

\export writes query rows to a CSV, JSON, or YAML file:

\export csv select * from titles
\export json to titles.json select id, title from titles where production_year > 2000
/export yaml to 'my titles.yaml' select * from titles
  • Without to <file>, the name is the first table after FROM plus a timestamp, such as titles-20261014-134650.csv. At the prompt, you can edit the suggestion. In a script, the shell uses it.
  • Quote a file name with spaces. An existing file is replaced.
  • JSON and YAML have the same shape as --format. CSV has a header row. In CSV, NULL is an empty field, BYTES is base64, and arrays and JSONB are JSON text.
  • Rows are written to a temporary file. A failed query doesn't change the target file.

  • Catalog. Enter on a database selects it with use. Space puts the selected name into the editor. The catalog reloads after DDL in this session. Press F4 to see changes from other sessions.

Scripts and automation​

Run SQL with -e​

camus-cli northwind -e "select * from users"
camus-cli demo -e "insert into users (id, name) values (1, 'Ada'); select * from users"
camus-cli demo -e "select * from users\G" > users.txt

The output matches the prompt, without the banner. A failed statement makes the process exit with status 1.

Run a .sql file with -f​

camus-cli northwind -f schema.sql
cat schema.sql | camus-cli northwind -f -
camus-cli demo -f seed.sql -e "select count(*) from users"

-f streams the file. This means that the file size doesn't matter. At the first failed statement, -f prints the error and the line of the statement, and it exits with status 1. -f - reads standard input. With -f and -e together, the file is executed first.

Source files​

source ./seed.sql
source ./seed.sql --force

source executes a file from the prompt, with the same rules as -f. --force continues after failures and prints a summary at the end. Note that a failure in an open transaction stops the file. The server ends that transaction.

Statements split at semicolons outside:

  • Single-quoted and double-quoted strings, and backtick identifiers.
  • Dollar-quoted bodies ($$ … $$, $tag$ … $tag$).
  • -- and # line comments, and /* */ block comments.

The JSONB operators #>, #>>, and #- aren't read as comments. The shell reads doubled quotes ('it''s') and backslash escapes. It removes the comments before it sends a statement.

JSON and YAML output​

Use --format json or --format yaml with -e or -f when a program reads the rows:

camus-cli demo -e "select id, name from users" --format json | jq '.[].name'
  • Standard output contains only rows. The status lines and the errors go to standard error.
  • Each statement that returns rows writes one document: a JSON array of objects, or a YAML sequence of mappings separated by ---. No rows writes []. DDL writes no document.

Read-only mode​

Start the shell with --read-only to prevent accidental writes, for example when you inspect a production database:

camus-cli northwind --read-only

The shell sends only these statements:

  • SELECT, WITH queries, and set operations.
  • EXPLAIN, SHOW, DESC, and DESCRIBE.
  • BEGIN, START TRANSACTION, COMMIT, ROLLBACK, and SET TRANSACTION.
  • Shell commands such as use, \d, and \export. \export checks its query.
  • backup list, backup chain, and backup gc preview.

The shell doesn't send other statements, including statements that it doesn't recognize. It also checks for writes that the first word hides:

  • A WITH clause before a write statement.
  • Locking reads, such as FOR UPDATE or FOR SHARE.
  • Calls to nextval or setval.
  • ANALYZE <table>, which stores new statistics.
camus> delete from users where id = 1;
Refused by --read-only: DELETE is not a statement that only reads.
The shell did not send the statement. To run writes, start the shell without --read-only.

A statement that the check stops doesn't reach the server, and an open transaction continues. With -e or -f, the script stops with exit status 1.

The check is in the shell, and it doesn't read C# function bodies. Use it to prevent mistakes. To make sure that a user can't write, give that user a server account with read privileges only.

Prepared statements​

After the driver sees the same SQL text twice, it prepares the statement on the server and reuses it. The result is identical to an inline run. show prepared shows the state of the last statement, or of the statement that you pass:

camus> show prepared
Prepared statements: 1 (MaxAutoPrepare=128, AutoPrepareMinUsages=2)
  prepared     select id from robots where year = 1984
(the statement you ran last)

A typed statement usually shows inline. Its literal values make the text different each time. Statements from source files and applications repeat exactly and reach prepared form. Set the thresholds in the connection string:

  • MaxAutoPrepare is the number of statements kept prepared. 0 turns the feature off.
  • AutoPrepareMinUsages is the number of executions before the driver prepares a statement.

See Prepared statements.

Backups​

The backup commands take and manage online backups while the server serves traffic:

backup full                            take a full backup
backup incremental <parent-backup-id>  add an incremental backup to a chain
backup coordinated                     take a cluster-wide consistent backup
backup list                            list the node's backup catalog
backup chain <leaf-backup-id>          find and validate a restore chain
backup gc preview                      show what retention would delete
backup gc                              run retention now
camus> backup full
    Backup Id: 971a0a88-3d36-42c6-b36b-8d1e773f40c4
         Type: Full
Created (UTC): 2026-08-10 03:45:47
       Parent: (none)
   Partitions: 4
Backup OK (00:00:03.117)
  • A backup covers all databases of the node. This means that it doesn't need a current database.
  • The commands work at the prompt and in scripts. They don't work in --tui.
  • The server must have backups configured (kahuna.backup_dir). Otherwise, each command returns CADB0700.
  • With authentication on, connect as a superuser. With authentication off, the server allows backup calls from the same machine (loopback) only.
  • The backup API is REST only. With a -c connection string that sets Protocol=grpc, add BackupEndpoint= with the server's HTTP endpoint.
  • backup coordinated must reach the backup coordinator, the node that currently leads backup metadata. When Endpoint lists several nodes, set BackupEndpoint= to the coordinator.
  • BackupTimeout= sets the backup timeout in seconds. The default is 300.
  • backup chain checks that a chain can restore before you need it.
  • An incremental backup becomes a full backup when its parent is past the retention floor. The command shows the change.

Retention starts after each backup and on a timer. Use backup gc to free space at once after you lower a limit. backup gc preview doesn't delete anything.

The shell cannot restore. See Backup and restore.

Authentication​

CamusDB authentication is off by default. On a server with authentication on, sign in with a user:

camus-cli northwind -u app         # prompts for the password
CAMUS_PASSWORD=app-secret camus-cli northwind -u app

The driver sends the password once and receives a short-lived token. Later statements send only the token, and the driver renews it before it expires.

  • -p with no value also prompts. Avoid -p <password> on a shared host. Other users can read the command line of a process.
  • CAMUS_USER and CAMUS_PASSWORD set the defaults. User= and Password= in -c also work. A flag overrides the same key in -c.
  • --token or CAMUS_ACCESS_TOKEN passes a token from another source. The shell doesn't renew it, and the session ends when the token expires.

Credentials aren't sent to an http:// endpoint on another machine. The shell returns CADB0519 before the password leaves the machine. Use https:// for remote servers. If TLS ends in front of the server on a trusted network, add --allow-insecure-credentials. The shell then prints a warning and connects.

Manage users and grants from a superuser session. These statements need no current database:

CREATE USER app IDENTIFIED BY 'app-secret';
GRANT SELECT, INSERT ON northwind.* TO app;
SHOW GRANTS FOR app;

See Authentication and authorization and the error codes CADB0516 to CADB0519.

Troubleshooting​

Terminal detection​

The rich editor and --tui need an interactive ANSI terminal. Some terminals report an unknown TERM value, such as Rio (TERM=rio). The shell then uses a simple prompt. Check what the shell detects:

camus-cli --diagnose-terminal

To use the rich editor on such a terminal, do one of these:

  • Add --force-rich.
  • Set CAMUS_FORCE_RICH=1.
  • Run with a known TERM, for example TERM=xterm-256color camus-cli.

The shell does not exit​

A transaction is open. Run commit or rollback first.

An old version starts​

camus-cli -v
dotnet tool update --global CamusDB.SqlSh --no-http-cache

NuGet caches package feed responses for up to 30 minutes. This means that an update can miss a version that was published recently. --no-http-cache reads the feed again.
