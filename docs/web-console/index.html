Web Console

The CamusDB Web Console lets you browse, query, and administer a CamusDB node or cluster from a browser, so you do not need a SQL client on each machine. You run the console once, with Docker or from source, and open it in any browser.

In the console you can browse schemas, run SQL, inspect results, edit small result sets, export tables, view node configuration and engine metrics, read EXPLAIN plans as visual flows, and administer backups.

Requirements​

  • A running CamusDB server.
  • Docker, or the .NET 10 SDK when running from source.

By default, CamusDB serves REST on port 5095 and client gRPC on port 5096. The Web Console can use either protocol.

Run it with Docker​

The Docker image contains everything needed to run the console:

docker run --rm -p 8080:8080 \
  -e CamusDB__Endpoint=http://host.docker.internal:5095 \
  -e CamusDB__Database=demo \
  camusdb/camusdb-webconsole:latest

Open this address:

http://localhost:8080

With Docker Desktop, host.docker.internal reaches CamusDB on the host machine. A Linux host may not provide that DNS name. In that case, use the host's LAN IP, or add this option:

--add-host=host.docker.internal:host-gateway

On first load, the console uses its configured defaults. Use the Configure control in the app bar to change the endpoint, database, protocol, backup endpoint, timeout, maximum rows, and credentials for the current browser session.

Configuration​

The Web Console reads the CamusDB configuration section. In a container, set the same keys as environment variables with two underscores.

SettingEnvironment variableDescription
EndpointCamusDB__EndpointCamusDB base URL. Use the REST port for rest and the gRPC port for grpc.
DatabaseCamusDB__DatabaseSession database name.
ProtocolCamusDB__Protocolrest by default. Also accepts grpc.
TimeoutSecondsCamusDB__TimeoutSecondsRequest timeout.
MaxRowsCamusDB__MaxRowsRows per page for pageable queries, and the cap for other results and exports.
UserCamusDB__UserUser to authenticate as. An empty value means no authentication.
PasswordCamusDB__PasswordPassword for User.
AccessTokenCamusDB__AccessTokenA bearer token from another source. The console uses it instead of a login.
RequireAccessTokenCamusDB__RequireAccessTokenRefuse user/password sign-in. The console then accepts access tokens only.
AllowInsecureCredentialsCamusDB__AllowInsecureCredentialsAllow credentials to a non-loopback http:// endpoint. Use only behind a trusted TLS terminator, private link, or tunnel.
LockEndpointCamusDB__LockEndpointPrevent browser sessions and vendor launch payloads from changing the configured endpoint or protocol.
TokenLifetimeSecondsCamusDB__TokenLifetimeSecondsFallback token reuse window when the server reports no expiry.
BackupEndpointCamusDB__BackupEndpointOptional REST endpoint for backup administration. Use it when the main protocol is gRPC, or when the main endpoint is a pool and backups must target one node.
BackupTimeoutSecondsCamusDB__BackupTimeoutSecondsOptional timeout for backup administration calls. 0 uses the client default.

For example:

{
  "CamusDB": {
    "Endpoint": "http://localhost:5095",
    "Database": "test",
    "Protocol": "rest",
    "TimeoutSeconds": 30,
    "MaxRows": 1000,
    "User": "",
    "Password": "",
    "AccessToken": "",
    "RequireAccessToken": false,
    "AllowInsecureCredentials": false,
    "LockEndpoint": false,
    "TokenLifetimeSeconds": 0,
    "BackupEndpoint": "",
    "BackupTimeoutSeconds": 0
  }
}

Protocol=grpc needs an Endpoint that points at the gRPC listener, usually http://localhost:5096.

Set LockEndpoint to true when the console is reachable beyond localhost and users should not be able to repoint the server process at another CamusDB endpoint. The same lock also applies to vendor-launched sessions.

Backup administration uses CamusDB's REST backup API. If the console connects to CamusDB through gRPC, set BackupEndpoint to the HTTP/REST endpoint. If the main Endpoint is a comma-separated pool of nodes, set BackupEndpoint to the specific node that should receive backup commands. A coordinated backup must reach the backup coordinator, the node that currently leads the cluster's backup metadata.

Security controls​

The Web Console has two local throttles in front of surfaces that an unauthenticated caller can reach: sign-in from the Configure dialog, and vendor launch endpoints. They are on by default under the Security section:

{
  "Security": {
    "LoginThrottleEnabled": true,
    "LoginFreeAttempts": 3,
    "LoginMaxAttempts": 10,
    "LoginSprayMultiplier": 5,
    "LoginWindowSeconds": 300,
    "LoginLockoutSeconds": 300,
    "LoginMaxDelaySeconds": 8,
    "MaxTrackedClients": 20000,
    "RateLimitEnabled": true,
    "LaunchPermitLimit": 30,
    "LaunchWindowSeconds": 60
  }
}
SettingEnvironment variableDescription
LoginThrottleEnabledSecurity__LoginThrottleEnabledCount and slow failed sign-ins from the Configure dialog.
LoginFreeAttemptsSecurity__LoginFreeAttemptsFailed sign-ins that add no delay.
LoginMaxAttemptsSecurity__LoginMaxAttemptsFailures for one address and one user before the console refuses to try for the lockout window.
LoginSprayMultiplierSecurity__LoginSprayMultiplierMultiplies the per-user limit to cap one address across all user names.
LoginWindowSecondsSecurity__LoginWindowSecondsHow long failures are remembered.
LoginLockoutSecondsSecurity__LoginLockoutSecondsHow long a refusal lasts.
LoginMaxDelaySecondsSecurity__LoginMaxDelaySecondsMaximum delay added before an attempt.
MaxTrackedClientsSecurity__MaxTrackedClientsMaximum number of client addresses kept in memory.
RateLimitEnabledSecurity__RateLimitEnabledRate-limit vendor launch endpoints per client address.
LaunchPermitLimitSecurity__LaunchPermitLimitRequests one address may make to each launch endpoint per window.
LaunchWindowSecondsSecurity__LaunchWindowSecondsLength of the vendor launch rate-limit window.

The client key is the socket peer address. The console does not trust X-Forwarded-For by default, because a caller can choose that header unless forwarded headers are configured carefully at the reverse proxy.

Authentication​

CamusDB authentication is off by default. Without a configured credential, the Web Console sends no Authorization header.

When a server starts with CAMUSDB_AUTH_ENABLED=true, sign in through the Configure control in the app bar with either:

  • A user and password.
  • An access token from another source.

The console exchanges the password once for a short-lived bearer token. Later statements send the token, not the password.

When the console has a password, it can renew a token before it expires, and it can sign in again if the server rejects a token early.

Session behavior:

  • Credentials entered in the Configure control belong to one browser session.
  • The console does not put the session password into the connection string.
  • The console remembers the user name in localStorage to prefill the dialog. It never stores passwords or access tokens there.
  • The identity chip in the app bar has a sign-out control. Signing out revokes a token that the console created, then drops the connection.
  • When you sign out, the console forgets a token you supplied. It does not revoke that token, because it did not create it.
  • The console cannot renew a token you supplied.

You can also configure User, Password, or AccessToken in appsettings.json or in a CamusDB__* environment variable, and the console then signs in automatically. Use an environment variable or a secrets store rather than committing a password.

Token-only consoles​

Set CamusDB__RequireAccessToken=true when the console must never accept a user/password sign-in. The Configure dialog then offers only the access token field, and the session service rejects any user or password supplied by a caller.

This pins the sign-in method, not the server's authentication policy. If the CamusDB server has authentication disabled, the console can still connect without an identity because the server allows it.

RequireAccessToken cannot be combined with configured User or Password. Startup fails instead of silently dropping those credentials. A supplied token is not renewable, so the browser session ends when the server expires it.

Manage users and grants with SQL from a superuser session:

CREATE USER app IDENTIFIED BY 'app-password';
GRANT SELECT, INSERT ON app_db.* TO app;
SHOW GRANTS FOR app;

A user without SELECT on a table still sees the table name in the schema tree, but the tree shows its columns as unavailable because the user lacks the privilege.

TLS​

While authentication is enabled, CamusDB refuses credential-bearing requests over plaintext, except from loopback. Local development over http://localhost works without a certificate. For any deployment beyond loopback, point the console at an https:// CamusDB endpoint.

If TLS terminates before requests reach CamusDB, keep that plaintext hop inside your trust boundary and configure CamusDB with --require-tls-when-auth-enabled false.

The driver also refuses credentials to a non-loopback http:// endpoint before anything is sent. Set CamusDB__AllowInsecureCredentials=true only when that plaintext hop is protected by another mechanism, such as a private network, VPN, SSH tunnel, or a trusted TLS terminator.

Authentication errors​

Authentication failures use the codes CADB0516 to CADB0519. See Error codes for what each one means.

Vendor launch​

An external product can open the console with its own branding and a CamusDB access token that the user's browser never sees. This is useful when another application already authenticates users and wants to offer a database console inside that workflow.

The launch surface is off by default:

{
  "ConsoleLaunch": {
    "Enabled": false,
    "ApiKey": "",
    "RequireHttps": true,
    "CodeLifetimeSeconds": 60,
    "SessionLifetimeMinutes": 60,
    "DefaultBrandName": "CamusDB Web Console",
    "MaxLiveEntries": 2000,
    "AllowedEndpoints": [],
    "PublicBaseUrl": ""
  }
}
SettingEnvironment variableDescription
EnabledConsoleLaunch__EnabledEnables the vendor launch endpoints. Disabled endpoints answer like ordinary missing routes.
ApiKeyConsoleLaunch__ApiKeyShared key sent as X-Console-Key. It must be at least 32 characters when launch is enabled.
RequireHttpsConsoleLaunch__RequireHttpsRefuse to mint launch links over plaintext. Keep true unless TLS terminates before the console.
CodeLifetimeSecondsConsoleLaunch__CodeLifetimeSecondsLifetime of the single-use redirect code.
SessionLifetimeMinutesConsoleLaunch__SessionLifetimeMinutesLifetime of the launched browser session.
DefaultBrandNameConsoleLaunch__DefaultBrandNameName shown when no vendor launch is active.
MaxLiveEntriesConsoleLaunch__MaxLiveEntriesCap for live launch codes, sessions, and handoffs. At the cap, new launches fail closed.
AllowedEndpointsConsoleLaunch__AllowedEndpointsOptional allowlist for CamusDB endpoints accepted from launch payloads.
PublicBaseUrlConsoleLaunch__PublicBaseUrlAbsolute public console URL used to build returned launch links.

Generate ConsoleLaunch__ApiKey with a cryptographically secure source, for example:

openssl rand -base64 32

The flow has two steps:

  1. The vendor backend calls POST /api/console/sessions with X-Console-Key and a JSON payload.
  2. The vendor redirects the browser to the returned launchUrl.

Example backend call:

curl -X POST https://console.example.com/api/console/sessions \
  -H "X-Console-Key: $CONSOLE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
        "brandName": "Acme Data Console",
        "accessToken": "<camusdb-access-token>",
        "database": "analytics"
      }'

The response contains a single-use URL:

{
  "launchUrl": "https://console.example.com/console/launch?code=...",
  "expiresInSeconds": 60
}

The token moves only from the vendor backend to the console backend. It is not put in the URL, page HTML, localStorage, or JavaScript-readable state. The browser receives an opaque session cookie.

brandName is validated before it is shown. It allows common letters, digits, spaces, and punctuation such as -_.,&'()+, up to 64 characters. Control characters, path separators, angle brackets, quotes, backticks, and emoji are rejected.

Endpoint safety​

A launch payload may include endpoint and protocol. The console process opens that endpoint, so allowing arbitrary values can let a caller make the console reach internal hosts. Use one of these controls for any deployed console:

  • Set CamusDB__LockEndpoint=true to reject endpoint overrides.
  • Set ConsoleLaunch__AllowedEndpoints to a comma-, semicolon-, or whitespace-separated allowlist.

Allowed endpoint entries can be full origins or host patterns without wildcards:

ConsoleLaunch__AllowedEndpoints="https://db.acme.example,db.internal.example:5095"

There is no wildcard syntax. Invalid entries fail startup instead of being silently skipped.

Features​

The Web Console provides:

  • A console layout with dark and light themes: an app bar, a schema sidebar, a SQL editor, a results grid, and a connection footer.
  • A configuration dialog for the endpoint, database, protocol, backup endpoint, timeout, row cap, and credentials.
  • A schema browser built on SHOW DATABASES, SHOW TABLES, SHOW COLUMNS FROM, SHOW INDEXES FROM, SHOW CREATE TABLE, SHOW SEQUENCES, schema comments, foreign-key metadata, sequences, and branch metadata.
  • The Monaco SQL editor.
  • CamusDB SQL highlighting and completion for keywords, functions, tables, and columns in the current schema.
  • Run statement runs the statement at the cursor with Ctrl/Cmd+Enter, or only the selected SQL when there is a selection.
  • Run script runs each statement in order with Alt+X, stops at the first failure, and gives each statement its own result tab.
  • A multi-tab query workspace.
  • Cancellable query runs.
  • Execution times and a status bar.
  • Searchable query history with database, duration, row count, and errors.
  • A paged, sortable, and filterable result grid that knows the types, including exact NUMERIC text.
  • A flow view for EXPLAIN and EXPLAIN (ANALYZE) results, beside the raw result table.
  • Context actions to rename databases, tables, columns, indexes, and sequences, and to edit data, export tables, change schema, or delete objects.
  • Row edit and delete actions when a result set comes from a table context.
  • CSV and JSON export for tables or the rows currently loaded in any result.
  • Administration pages for node-local engine metrics, effective variables, and backup controls.
  • Interface preferences remembered in the browser's localStorage, such as open SQL tabs, editor text, the active database, the user name, the schema drawer width, the editor/results split, and query history. The theme choice is remembered in a browser cookie so the correct theme is painted before the app connects.

Double-click a table in the schema tree to insert:

SELECT * FROM table_name
LIMIT 100

Right-click a database to create, rename, or drop it. The create-table dialog can define columns, primary keys, single-column foreign keys, and defaults such as nextval('sequence') or NUMERIC '9.99'.

Right-click a table to view or edit data, rename it, add a column, add an index, add a foreign key, export the table, or drop the table. Columns and indexes can also be renamed from their context menus. The add-column dialog runs ALTER TABLE ... ADD COLUMN; a NOT NULL column needs a constant default because existing rows get that value. The add-foreign-key dialog can create multi-column foreign keys and lets the server validate existing rows.

Foreign keys appear under the table. Hover one to see its columns, referenced table, and ON DELETE / ON UPDATE actions. Right-click a foreign key to drop the constraint.

Sequences appear after tables. Double-click a sequence to insert SHOW CREATE SEQUENCE ...; right-click one to show, rename, or drop it. Dangerous actions require confirmation.

Query behavior​

The console routes SQL by statement shape:

  • Statements that return rows, such as SELECT, SHOW, EXPLAIN, and WITH, render into the result grid.
  • INSERT ... RETURNING, and other write statements with a RETURNING clause, render the returned rows into the result grid and show the affected-row count.
  • DML and DDL statements render affected row counts and status messages.
  • Database lifecycle actions in the schema browser run through the same database-level operations exposed by CamusDB.

For a SELECT without its own LIMIT or OFFSET, MaxRows is the page size. Use Fetch more to append the next page. Add an ORDER BY when page order must be stable. Other row-returning statements are capped at MaxRows and report when the result was truncated.

When part of the editor text is selected, Run statement executes only the selection. Otherwise it finds the statement at the cursor. Run script splits the selection or tab at semicolons outside strings, quoted names, and comments.

The history control records the last 200 statements in localStorage and can search or reopen them in a new tab. Password literals in CREATE USER and ALTER USER are masked before storage.

The result grid styles values by type. It distinguishes NULL, numbers, booleans, timestamps, blobs, UUIDs, exact NUMERIC values, and ordinary strings, and it warns when the result was truncated by MaxRows.

Click a column heading to sort loaded rows, and use Filter loaded rows for a client-side filter. In an Edit/View Data tab, sorting and the WHERE box are sent to the server and reflected in the tab's SQL.

Query plan flow​

When a statement returns an EXPLAIN, EXPLAIN (LOGICAL), EXPLAIN (PHYSICAL), or EXPLAIN (ANALYZE) result, the toolbar above the result adds a Table / Flow switch. Table shows the raw rows returned by CamusDB. Flow draws the plan as a diagram, with the source operator at the top and each operator below the one that feeds it.

Each operator card shows the operator family, the server's detail text, the table or index involved, and its share of the estimated cost. The console marks the highest-cost operator, so you can spot expensive parts of a plan without scanning every row of the EXPLAIN table.

The edges show the estimated row flow between operators. With EXPLAIN (ANALYZE), the flow also includes measured rows, rows read, KV lookups, KV scan entries, and the measured plan time. When an operator's measured row count is far away from the estimate, the diagram marks it as an estimate miss.

Joins have a right input that is described in the join row rather than emitted as a separate plan row. The flow renders that input as a dashed side box beside the join, using the alias, index, or subquery table that the detail text contains.

Rows that describe the whole plan, such as plan-info, distribution, and cache, appear below the diagram as plan notes. The console remembers whether you last used Table or Flow, so the next plan opens in the same view.

Row editing​

Edit/View Data on a table opens a data tab. The tab runs SELECT * for that table and attaches the table schema to the result, which enables row actions.

The edit dialog is generated from the table schema:

  • Primary-key fields are read-only.
  • Nullable fields get a NULL toggle.
  • Values are validated against the column type before the console builds the SQL statement.
  • NUMERIC values are kept as canonical decimal text and written back as NUMERIC '...', so large exact decimals are not rounded through .NET decimal or JavaScript number.
  • UPDATE and DELETE use the table primary key.

If a table has no primary key, edit and delete row actions are disabled with a Primary key required hint. After a successful edit or delete, the data tab refreshes its query.

Administration​

The Administration page exposes node-local operational views:

PanelWhat it shows or does
Engine statsRuns SHOW ENGINE STATS and displays the metrics of the node that answered.
VariablesRuns SHOW VARIABLES and displays effective configuration values for the node that answered.
BackupsTakes full, incremental, and coordinated backups; lists the backup catalog; validates a chain; previews or runs retention garbage collection.

These views are node-local: they show only the node that answered, and do not forward to another node. To compare a cluster, point the console at each node.

When authentication is enabled, Administration requires a superuser. Engine metrics describe node-level workload, variables describe the node's security and runtime posture, and backups cover every database on the node.

Backups are available only when the server has backup configuration. See Backup And Restore for backup setup, retention, coordinated backups, and offline restore.

Export​

A table export runs SELECT * FROM <table>, capped by the current session's MaxRows. The result toolbar can also export the rows currently loaded by any query, after the grid's sort and filter. For a paged result, use Fetch more before exporting if you need more rows. The console downloads CSV or JSON.

CSV uses proper quoting and escaping. JSON downloads an array of objects with dates as ISO-8601 strings, blobs as hex, UUIDs in standard textual form, and NUMERIC values as strings so no digits are lost.

If the table holds more rows than MaxRows, the export reports that the result was truncated.

For a full logical backup or a restorable SQL dump, use camus-dump instead.

Notes​

  • The console browses schemas with SQL SHOW statements.
  • The console does not use metadata-only client endpoints.
  • The console is an operations UI, not an authorization boundary by itself. Authentication and grants on the CamusDB server remain the durable permission boundary.
  • The console sends security headers that prevent framing, reduce MIME sniffing, and avoid leaking referrer details.
